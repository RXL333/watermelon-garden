# 西瓜小院

手机浏览器优先的单人水果合成游戏。原创水果插画、物理堆叠、落地挤压、合成回弹、连锁音效、大西瓜庆祝、本机存档和水果图鉴。

在线游玩：[西瓜小院](https://rxl333.github.io/watermelon-garden/)。手机浏览器打开即可开始，无广告，无需登录。

## 本地运行

需要 Node.js 22.12 或更新版本，推荐 Node.js 24。

```sh
npm install
npm run dev
```

手机与电脑连接同一局域网后，可以打开终端显示的 Network 地址。正式发布使用 HTTPS。

## 操作与规则

- 手机：按住游戏区域左右移动，松手投下水果。
- 电脑：移动鼠标瞄准、点击投放；也支持左右方向键、空格投放和 Z 撤回。
- 两颗相同水果碰撞后合成下一级。合出西瓜仍可继续挑战；两颗西瓜相遇后消失，获得 500 分。
- 首页可选择轻松、经典、挑战三档；游戏中点击底部难度按钮，或在暂停菜单中更换难度。更换前会提示开始新局，取消则继续原局。
- 已投下水果有 1.4 秒入场宽限；持续越过警戒线达到当前难度的宽限时间后结束。暂停期间不累计。
- 离开页面自动保存，切到后台会暂停。进度与最佳分保存在当前浏览器、当前站点中，不跨设备同步。
- 三档分别记录最佳分，共享水果图鉴；续局自动恢复原来的难度。旧版本存档与最佳分归入经典档。
- 每局有 3 次撤回机会，回到最近一次投放前，包括随后的合成、得分、水果位置与速度、随机队列和越线计时。一次投放只能回退一次；剩余次数随存档保存。已取得的最佳纪录和图鉴发现会保留。
- 瞄准相同水果时，会显示柔和的匹配光圈；底部进化条标记本局最高水果和下一目标。图鉴里的每个水果都可以点开放大查看。
- 新版存档保留下落、旋转速度和入场宽限，减少刷新后的运动突变；结算显示本局投放数量和最高水果。
- 投放、有效撞击、合成和消除支撑时会唤醒果堆，使接触力能继续传到下层。合成水果的真实碰撞圆在 160ms 内长大，并对邻近水果施加短暂局部压力；较低的滚动阻力和更精细的接触求解让上下层能重新下沉、挤压和滚动。平静后仍会休眠。
- 暂停菜单提供轻柔动效开关，系统减少动态效果偏好也会被尊重。

| 难度 | 水果半径 | 随机投放范围 | 越线宽限 |
| --- | --- | --- | --- |
| 轻松 | 经典的 88% | 葡萄至蜜橘，4 种 | 3 秒 |
| 经典 | 标准大小 | 葡萄至柠檬，5 种 | 2 秒 |
| 挑战 | 经典的 108% | 葡萄至猕猴桃，6 种 | 1.2 秒 |

合成顺序、得分和投放冷却在三档中相同；开局固定提供两颗葡萄。难度参数集中在 `src/rules.ts`，可继续根据实际游玩反馈调整平衡。

## 发布到 GitHub Pages

1. 将项目文件推送到 GitHub 仓库的 `main` 分支。
2. 仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。
3. `.github/workflows/deploy.yml` 会安装依赖、运行测试、构建并发布 `dist`。

构建采用相对资源路径，支持 `https://用户名.github.io/仓库名/` 和站点根路径。

```sh
npm test
npm run build
npm run preview
```

也可以将 `dist` 内的文件直接作为静态网站发布。若手动用 Pages 分支发布，将 `dist` 内容放在发布目录，并添加空文件 `.nojekyll`。

需要压缩发布包时，可在构建后运行 `python scripts/package-release.py`，生成 `artifacts/watermelon-garden-web.zip`。此脚本按当前版本的资源清单打包，适合本地保留过多次构建的情况。

生产构建自动生成 Service Worker，缓存当前版本所需文件；首次完整加载并缓存成功后，支持离线再次打开。浏览器清理站点数据会同时删除缓存和存档。开发模式不启用离线缓存。

## 实现位置

- `src/game.ts`：固定步长物理、投放、合成、危险线和动画。
- `src/rules.ts`：水果尺寸、得分、随机权重、配对规则和存档验证。
- `src/main.ts`：手机版界面、暂停、图鉴和结算。
- `src/style.css`：手机竖屏、安全区、小屏与横屏布局。
- `src/audio.ts`：本地 Web Audio 合成音效，无外部音频请求。
- `src/fruit-art.ts`：界面与物理场景共用的水果裁切框和主体对齐数据。
- `src/physics-state.ts`：运动状态的保存与恢复。
- `src/physics.ts`：物理材质、休眠唤醒、真实碰撞体生长和合成压力。
- `public/assets/fruit-atlas-v2.png`：修正叶冠、果梗与分格边界的原创水果图集，详情见 `ASSETS.md`。

## 开发验收

`npm test` 覆盖重复碰撞、三果配对、独立合成、双西瓜、判负宽限、出果概率、随机队列续接、三档投放边界、损坏存档、难度恢复、独立最佳分与旧存档迁移。

本轮新增撤回次数与历史持久化、原队列回退、真实 Matter 引擎的下落与旋转恢复，以及整套水果的透明边距、叶冠/果梗与裁切完整性检查。

物理专项回归覆盖失去支撑后下落、碰撞体生长、五层果堆的接触传递、生长途中续局、平静后恢复休眠，以及 64 次连续投放触发实际合成的稳定性。

开发服务器可打开 `/?qa=retina`，使用可见按钮预置三果碰撞、合出西瓜、双瓜清空、满箱结算场景，并以 2 倍画布分辨率检查触点映射。该入口会改写开发站点的测试存档；验收面板不会出现在生产构建中。

浏览器已检查 390×844、375×667、320×568 布局，以及普通合成、拖动、暂停、刷新续局、连续投放、三果配对、西瓜庆祝、双瓜奖励、满箱结算和结算后的图鉴返回。

在缓存就绪后停止本地服务器，已验证桌面浏览器可离线重新打开并恢复对局。详细范围见 `TESTING.md`。

真实 Android / iOS 手机的触控、后台切换、声音、长时间性能和飞行模式下的离线启动仍需真机验收；本地开发机器上的检查不能替代这些项目。
